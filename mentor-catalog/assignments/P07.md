# P07 — Стенд Compose и восстановление данных

Неделя 7. 10–12 часов. До начала: Принят P06.

Команде нужен единый запуск приложения с reverse proxy и проверенный способ восстановить каталог после ошибочного изменения данных.

## Что важно понять

Compose описывает несколько связанных сервисов. Имена сервисов работают внутри сети Compose. Успешное создание архивного файла еще не доказывает возможность восстановления: проверять нужно содержимое и поведение приложения.

## Задание

1. Создай compose.yaml для app и nginx. Опубликуй только порт proxy на 127.0.0.1 учебного хоста, backend доступен по имени app внутри сети.
2. Подключи каталог данных отдельно от образа через bind mount либо named volume. При первом запуске скопируй demo/items.json в данные явным шагом; повторный запуск не должен затирать измененные записи.
3. Добавь health check приложения, объясни различие порядка запуска и готовности. Подготовь env.example и инструкцию всех переменных.
4. Напиши backup.sh, который копирует согласованный учебный dataset и проверяет архив. Для этого read-only приложения запрети редактирование файла на время backup; для реальной БД нужен собственный механизм backup.
5. Восстанови архив в отдельный каталог и подними второй стенд с другим project name и портом. Сравни количество и содержимое /items с эталоном.
6. Измени данные тестовой копии и восстанови их. Запиши время восстановления и фактическую потерю изменений после последней копии.

## Приемка

- Одна описанная команда поднимает два сервиса, /items доступен через proxy.
- Пересоздание контейнеров сохраняет учебные данные; повторная инициализация их не затирает.
- Второй независимый стенд действительно читает восстановленный dataset.
- Документация различает restart, recreate и удаление volume; backup-процесс не выдается за универсальное решение для PostgreSQL.

## Учебная неисправность

- В отдельной копии стенда укажи неверный DATA_FILE. Диагностируй 503 на /items, при том что /healthz продолжает отвечать 200.
