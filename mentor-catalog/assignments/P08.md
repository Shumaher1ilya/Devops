# P08 — Проверяемый релиз и учебный инцидент

Неделя 8. 10–12 часов. До начала: Принят P07.

Каждый PR должен автоматически проверяться, а релиз — иметь доказательство работоспособности. В конце недели ты передаешь сервис другому инженеру и устраняешь неизвестную неисправность.

## Что важно понять

CI запускает проверки изменений в контролируемой среде. Артефакт релиза должен однозначно связываться с исходным коммитом. Откат приложения и восстановление данных — разные операции с разными последствиями.

## Задание

1. Выбери одну CI-платформу: GitHub Actions по умолчанию или GitLab CI. Запускай на PR тесты Python, проверку Bash, сборку образа и smoke test контейнера.
2. Для smoke test создай изолированные demo-данные, запусти контейнер, дождись готовности с ограниченным timeout, проверь /healthz, /version и /items. Заверши контейнер даже при падении проверки.
3. Задай минимальные права CI; не передавай секреты недоверенному коду PR. Сохраняй полезные логи при неуспехе. Реальный деплой на VM в минимальный объем не входит.
4. Создай намеренно сломанный PR: тест либо ожидаемая версия не совпадает. Покажи красную проверку, исправление и зеленый запуск.
5. Собери релиз по commit SHA, выполни ручной deploy и rollback в лаборатории по своему runbook.
6. Попроси ментора выбрать одну изученную поломку. Зафиксируй симптомы, гипотезы, факты, восстановление и профилактику в docs/postmortems/p08.md. Передай стенд и README ментору.

## Приемка

- Сломанный PR дает красный pipeline, исправленный — зеленый; проверки не состоят из echo-заглушек.
- Ментор по чистому clone запускает сервис и видит ожидаемую версию.
- При smoke failure сохранены логи, процесс теста очищен; данные рабочего стенда не затронуты.
- Выполнены ручной rollback и восстановление копии; защита включает объяснение минимум одной новой диагностики.

## Git

- Ветка p08/ci, PR с красным и зеленым запуском, финальный тег v0.8.0. Запиши SHA и идентификатор собранного образа в release notes.

## Учебная неисправность

- Ментор выбирает одну неисправность: порт, upstream, права данных или ошибочная версия. Действия выполняются только на учебном стенде с подготовленным откатом.

## Теория

- [GitHub Actions — основные понятия](https://docs.github.com/en/actions/get-started/understand-github-actions) — Workflow, event, job, step, runner. В P08 достаточно тестирования и smoke test, облако не требуется.
- [GitLab — первый pipeline](https://docs.gitlab.com/ci/quick_start/) — Выбрать вместо GitHub Actions, если репозиторий в GitLab. Изучить stages, jobs, rules, artifacts и runner.
- [Google SRE Workbook](https://sre.google/workbook/table-of-contents/) — Разделы SLO, Monitoring, Alerting, Incident Response и Postmortem Culture. Выбирать по текущему проекту.
