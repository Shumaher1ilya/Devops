# Mentor Catalog — учебный проект DevOps

Это исходная точка для восьми недель практики. Сервис читает вымышленные записи
из JSON-файла. Сначала запусти его обычным Linux-процессом, затем добавляй
systemd, Nginx, автоматизацию, Docker, Compose и CI по заданиям.

## Требования

- Python 3.10 или новее. Сторонних Python-пакетов нет.
- Linux VM с systemd для P01–P05; Git, SSH и curl.
- Собственный репозиторий на GitHub или GitLab.

## Первый запуск

Из корня проекта на Linux:

```bash
python3 app.py
```

В другом терминале:

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/version
curl -fsS http://127.0.0.1:8080/items
```

Остановить процесс: Ctrl+C в первом терминале. `/healthz` возвращает
`{"status":"ok"}`, `/version` — `{"version":"dev"}`, `/items` — три demo-записи.
Запуск не изменяет данные. Чтобы создать свою учебную копию данных:

```bash
mkdir -p data
cp demo/items.json data/items.json
DATA_FILE=data/items.json APP_VERSION=v0.1.0 python3 app.py
```

Копирование выше делается один раз. Автоматизация не должна повторно затирать
измененные данные demo-файлом. `env.example` — справочник переменных, приложение
самостоятельно не читает `.env`. В shell используй окружение команды, в systemd
— EnvironmentFile, а позднее в Compose — соответствующую конфигурацию.

## Контракт приложения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| BIND_HOST | 127.0.0.1 | Адрес, который слушает процесс |
| PORT | 8080 | TCP-порт |
| APP_VERSION | dev | Значение GET /version |
| DATA_FILE | demo/items.json | Путь к JSON-массиву |

`GET /items` возвращает 503, если dataset недоступен, поврежден или не является
массивом. `/healthz` при этом отвечает 200: живость и готовность различаются.
Неизвестный маршрут возвращает 404. Каждый GET создает JSONL-запись в stdout:
time, method, path, status, duration_ms. В этом сервисе нет POST и аутентификации.
Используй его только как учебный стенд с вымышленными данными.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Тесты создают сервер на случайном локальном порту и временные данные.
Рабочий dataset не изменяется. Функциональность тестов можно расширять.

## Маршрут и сдача

Открой [ROADMAP.md](ROADMAP.md), затем [P01](assignments/P01.md).
Для каждого этапа создавай ветку и PR. Шаблон описания PR уже находится
в `.github/pull_request_template.md`; для GitLab скопируй его в
`.gitlab/merge_request_templates/Default.md`.

В ходе курса создай `infra/`, `scripts/`, `docs/runbooks/` и `docs/postmortems/`.
Не добавляй в Git ключи, токены, backup и реальные данные. До каждого merge
проверь diff и список добавленных файлов. `.gitignore` не удаляет файлы,
которые уже попали в историю.

Этот архив не содержит готового решения инфраструктурных заданий.
После завершения каждого проекта обновляй README под реальное состояние сервиса.
